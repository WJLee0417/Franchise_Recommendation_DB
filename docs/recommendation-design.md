# 추천 설계

## 1. 전체 흐름

```text
입력 지역 특성 준비
→ DB 상권 특성과 컬럼 정렬
→ 식별 컬럼 제거
→ 결측치 보정
→ 코사인 유사도 계산
→ 유사 상권 후보 선택
→ 유사 상권 업종 매출 조회
→ 프랜차이즈 업종 코드와 JOIN
→ 휴리스틱 추천 점수 계산
```

## 2. 유사 상권

상권 통합 데이터의 43개 컬럼 중 코드·명칭·좌표 등 식별 목적의 7개 컬럼을 제외해 36개 특성으로 비교합니다.

제외하는 컬럼:

- 상권 구분 코드
- 상권 코드
- 상권 코드명
- X 좌표
- Y 좌표
- 자치구 코드
- 행정동 코드

결측치는 원본 구현과 동일하게 0으로 대체한 뒤 `sklearn.metrics.pairwise.cosine_similarity`로 입력 지역과 각 상권을 비교합니다.

## 3. 추천 점수

프로젝트 당시 추천 점수는 다음 구조의 규칙식으로 구성했습니다.

```text
추천점수 =
(
  유사상권 업종 매출
  + 프랜차이즈 당기순이익
  + 신규개점 가중치
  - 계약해지 가중치
  - 단위면적당 인테리어비
  - 교육비
  - 보증금
  - 기타비용
) / scale
```

SQL 구현은 `COALESCE`를 사용해 NULL을 0으로 처리합니다.

## 4. 해석 범위

이 점수는 학습된 예측 모델이 아니라 당시 프로젝트에서 정한 비교 규칙입니다. 따라서 다음과 같이 해석해야 합니다.

- 후보 브랜드를 상대적으로 정렬하는 기준
- 유사 상권의 업종 성과와 브랜드 비용·성과 지표를 함께 보는 탐색 도구
- 창업 성공 확률이나 기대수익을 예측하는 모델은 아님

## 5. 개선 방향

- 수치형 특성 표준화 후 유사도 변화 비교
- 결측치별 처리 전략 분리
- 추천 가중치 민감도 분석
- 기간이 다른 데이터의 기준 시점 정렬
- 학습·검증 데이터가 확보될 경우 순위 학습 또는 회귀 기반 평가와 비교
- 추천 결과에 각 지표의 기여도를 함께 출력해 설명 가능성 강화
