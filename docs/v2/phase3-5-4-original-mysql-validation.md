## DDL과 적재

사전 검증 통과 후 `007_snapshot_dimensions.sql`을 한 번 적용했다. MySQL 명령은 종료 코드 0이었고 5개 테이블의 `SHOW CREATE TABLE`과 정보 스키마에서 컬럼 자료형·NULL 조건, PK, 세 UNIQUE 제약, 네 FK 제약 및 CHECK 정의를 확인했다. DDL은 MySQL에서 자동 커밋되므로 중간 실패 시 수동 조사해야 하며, 자동 DROP이나 TRUNCATE는 수행하지 않았다.

| SNAP_INDUSTRY | 100 | 100 |
| SNAP_INDUSTRY_SOURCE | 163 | 163 |
| **합계** | **1,922** | **1,922** |

CLI dry-run은 9.422초였고 롤백 후 다섯 테이블의 지문이 모두 실행 전과 동일했다. 별도로 동일 트랜잭션에서 적재 결과를 전수 검사한 dry-run은 11.765초였고 롤백을 확인했다. 최초 실제 CLI 적재는 9.359초, 동일 데이터 재실행은 4.250초였다. 이 시간은 각 명령 자체의 경과 시간이며 사전 검사, 별도 최초·재실행 후 전수 비교 및 보고서 작성은 포함하지 않는다.

## 전수 비교와 멱등성

`scripts/verify_snapshot_dimensions_mysql.py`는 세 원본 문서의 결정적 스냅샷 ID·배치·해시·스코프를 비교하고, 2022Q1–2023Q2의 시작일과 exclusive 종료일 및 분기 사이 연속성을 검사한다. AREA 1,650행을 원본 행 ID로 연결해 코드, 명칭, 상권 유형, 자치구·행정동, 좌표와 면적을 전부 비교했다. 숫자는 Decimal 값으로 비교하여 표현 차이를 구분했다.

SALES·STORE의 모든 원본 레코드를 분기·업종코드·업종명으로 집계하고 스냅샷 코드·명칭과 대조했다. SALES 125,692행이 63개 업종, STORE 457,043행이 100개 업종에 각각 대응했고, 163개 문서–업종 연결의 `rows_observed`도 원본 집계와 정확히 일치했다. PK와 원본 업종 집합의 비교를 통해 각 원본 행이 보고분기와 업종에 각각 하나씩 대응함을 확인했다.

기존 로더의 재실행 경로는 개수와 문서 메타데이터만 확인한다. 이번에 추가한 검증기는 각 스냅샷 테이블을 PK 순서로 읽어 **모든 컬럼**의 SHA-256을 계산하고 원본과 다시 대조한다. 최초 적재와 재실행 후 PK 집합을 포함한 전체 컬럼 및 `created_at` 지문이 같았다. 재실행 로더는 `replayed=True`로 INSERT 경로에 진입하지 않고 반환하므로 INSERT·UPDATE·DELETE는 각각 0건이다. 이 외부 검증 절차를 생략하고 로더만 재실행하면 내용 변조를 전수 감지하지 못한다.

## 실패·복구와 기존 데이터 보존

실제 원본이 아닌 별도 Docker MySQL의 합성 스키마에서 적재 도중 상권 10행 삽입 직후 예외를 주입했다. 롤백 후 스냅샷 5개 테이블이 모두 비어 있었고 정상 재실행으로 1,922행을 적재했다. 합성 상권코드 중복, 업종코드의 명칭 충돌과 FK 위반도 거부되고 롤백됐다. 이미 적재된 합성 스냅샷의 전체 컬럼 지문은 오류와 재실행 후 유지됐으며, 값만 변경하고 행 수는 유지한 경우 지문이 변하는 것도 확인했다. 강제 운영체제 종료나 실제 원본 DB의 파손을 유발하는 시험은 하지 않았다.

DDL 전후 기존 **51개 기본 테이블**(기존 49개 모델과 Phase 3-4의 STG·실행 이력)을 PK 순서로 전체 컬럼 해시와 `SHOW CREATE TABLE` 해시로 비교한 결과 모두 동일했다. SRC 전체 행 수는 AREA 1,658, SALES 125,695, STORE 457,046으로 유지됐으며 여기에는 과거 합성 행이 포함된다. STG 전체는 584,385행이고 28개 기존 DIM·FACT는 전후 모두 0행이다. 뷰의 정의는 이 51개 기본 테이블 비교에 포함되지 않았다. 기존 및 신규 단위 테스트 21개와 합성 MySQL 복구 시험이 통과했다.

## 해석과 후속 단계

`SNAP_AREA`는 원본 AREA 문서의 목록이며 각 분기에 동일한 공식 공간 경계가 유효했다는 증거가 아니다. `SNAP_INDUSTRY`는 원본에서 관측된 업종 목록이며 공식 분류 발효일이 아니다. `SNAP_PERIOD`는 보고 분기이며 FACT의 관측기간을 임의로 동일하게 지정할 근거가 아니다. 기존 DIM·FACT나 Phase 3-5-5 FACT 적재는 수행하지 않았다.

스냅샷 기반 **Phase 3-5-5 설계·구현을 시작할 수 있다**. 다만 실제 FACT 적재는 이 제한을 유지하는 별도 계약과 검증이 필요하며, 본 결과는 공식 역사적 공간 버전이나 관측기간의 정확성을 보증하지 않는다.

집계와 전수 검증 결과는 Git에서 제외된 `data/local/phase35_snapshot_mysql_validation.json`, DDL 결과는 `data/local/phase354_schema.json`, 기존 테이블 지문은 `data/local/phase354_before.json`과 `data/local/phase354_after.json`에 보관한다. 원본 CSV·ZIP·비밀번호는 저장소에 포함하지 않는다.
