## 5. 정제 규칙 결정

규칙 ID는 `config/p0_quality_rules.v1.json` 참조.

| 판정 | 조건 | 처리 |
|---|---|---|
| **BLOCK** | 업무키 중복/빈값, 잘못된 분기, 필수 수치 비숫자, 비음수 수치 음수, 인구/점포/거래 **건수**의 소수 | SRC 원문은 유지, 변환 후보 격리 및 로그 |
| **WARN** | 개·폐업률>100, 유사업종 점포 수>점포수, 성별/연령별 매출·건수 총계 차이, STORE 매출 누락 | 원본값 유지, 품질 플래그만 추가 |
| **REVIEW** | 가맹점수>점포수, 이벤트 수>스냅샷 점포수, 시간대 음수 건수/합계 불일치, 0 비율과 양수 사건 | 특정 세부 분석 보류. 원천/코드북 확인 |
| **BLOCK_FOR_DIM** | AREA 유효기간·공간 버전 불명 | 상권차원 자동화 보류, SRC와 정제 스테이징은 계속 가능 |
| **BLOCK_FOR_FACT** | 상권차원 미확정 또는 통계 기준 기간/단위 미확정 | 새 FACT 적재 보류 |

**정제 시 금지:** 원본 수정·자동 삭제, NULL→0 일괄 대체, 이상치 상한 클리핑, 성별/연령별 구성값으로 원본 매출액 교체, 업종명/상권명 문자열 JOIN, 상권 유효기간 임의 생성.

## 6. Phase 3-4 후속 구현 관문

1. 먼저 SRC → **검증된 정제 스테이징** 변환의 판정 로그(ACCEPT/WARN/REVIEW/REJECT)와 재현 가능한 배치 결과를 구현한다. 이 문서는 룰 설계와 증거 기록만 포함하며 **원본 DB 정제·변환은 아직 수행하지 않았다**.
2. 시간대 거래 건수 음수 2셀/합계 불일치 4행은 세부 거래건수 분석에서 제외할 부분을 분리 기록한다. **총액/총건수는 그대로 사용 가능**.
3. 데이터 분석 지표의 명칭/단위·관측기간과 상권 경계 이력의 공식 근거를 확보한 후 DIM/FACT 적재 게이트를 검토한다.
