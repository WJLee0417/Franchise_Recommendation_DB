# Phase 3-5-2 후속: 1) 점포 지표 → 2) 역사적 상권 경계 → 3) 업종 분류·관측기간 (2026-10-29)

## 1순위 — 점포 지표: 원본→공식 필드 대응을 높은 신뢰도로 확인

서울시 점포-상권 공식 공개 데이터 OA-15577은 `STOR_CO`(일반 점포 수), `FRC_STOR_CO`(프랜차이즈 점포 수), `SIMILR_INDUTY_STOR_CO`(전체 점포 수)를 구별하며 전체=일반+프랜차이즈라고 안내한다. **과거 CP949 ZIP에 포함된 한글 헤더는 다르게 출력**되므로 같은 코드에 해당하는지 확인할 때 주의한다.

원본 **457,043행 전수**에서 `유사_업종_점포_수 = 점포_수 + 프랜차이즈_점포_수`가 정확히 성립한다(위반 0). 따라서 다음 의미 대응이 강하게 지지된다.

| 원본 한글 헤더 | 기존 SRC 컬럼 | 데이터 의미 | 현행 공식 영문 필드 |
|---|---|---|---|
| 점포_수 | store_count | **일반 점포 수** | STOR_CO |
| 프랜차이즈_점포_수 | franchise_store_count | 프랜차이즈 점포 수 | FRC_STOR_CO |
| 유사_업종_점포_수 | similar_industry_store_count | **전체 점포 수** | SIMILR_INDUTY_STOR_CO |

**기존 FACT_AREA_STORE.store_count를 '전체 점포 수'로 설명하면서 SRC.store_count를 적재하면 과소계상**된다. FACT 스키마의 `similar_industry_store_count` 역시 실제 의미인 일반점포와 이름이 맞지 않는다. 데이터 계약을 승인하고 명시적으로 컬럼을 재명명·확장할 때까지 G13 적재 차단을 유지한다. 기존 SRC/STG/FACT 원문이나 값은 바꾸지 않았다.

### 기존 품질 규칙 오류와 수정안 영향 (아직 미적용)

- P0-DQ-004 `유사_업종_점포_수>점포_수`는 **전체>일반**을 잘못 경고한 규칙이므로 폐지 제안.
- P0-DQ-005 `프랜차이즈 점포 수>점포 수`는 서로 다른 구성 부분 비교이므로 REVIEW 폐지 제안.
- P0-DQ-006 이벤트 수와 스냅샷 점포 수 비교를 할 때는 일반점포 수 대신 전체점포 수를 사용하는 방향을 **잠정 시뮬레이션**. 다만 이벤트 기준기간/분모를 공식 확인할 때까지 해당 규칙의 최종 승인을 보류한다.
- 이미 기록된 v0.1 STG 품질 판정과 해시는 **불변**으로 보존하고 새 정책 버전 v0.2를 분리 적용해야 한다.

`simulate_p0_store_quality_policy.py`가 원본 STORE CSV를 다시 전체 읽어 산출한 **가상 정책 v0.2 분포** (DB 미변경):

| 분류 | v0.1 기존 | v0.2 시뮬레이션 |
|---|---:|---:|
| ACCEPT | 383,390 | 453,607 |
| WARN | 49,873 | 0 |
| REVIEW | 23,780 | 3,436 |
| REJECT | 0 | 0 |
| **합계** | 457,043 | 457,043 |

- `WARN→ACCEPT` 49,873행, `REVIEW→ACCEPT` 20,344행. **총 70,217행** 판정이 달라진다. 기존 100% 초과 개·폐업률 등 WARN은 REVIEW 우선순위로 흡수될 수 있다.
- 이 수치는 **공식 신규 승인 결과가 아닌, 규칙 변경 영향 시뮬레이션**이다. 시뮬레이션의 경우 복잡한 중첩 이슈를 다르게 처리할 수 있으며, 실제 v0.2를 적용할 때 새 판정 로직으로 재계산해야 한다.

## 2순위 — 2022~2023 상권 경계: 파일 탐색 결과와 보류 사유

- 원본 ZIP 76개 항목을 검사: CSV 42개, XLSX 5개 등. **SHP/SHX/DBF/PRJ 지리 경계 세트는 없음**. 원본 `영역-상권.csv`에 `상권코드, 명칭, 중심 좌표, 면적`만 있고 경계 다각형·버전·유효시작일/종료일이 없다.
- 서울 공식 AREA 상권 데이터셋 **OA-15560** 및 골목상권 서비스 자료에서 SHP 다운로드 경로는 확인했지만, **2022~2023 당시 공식 경계 스냅샷을 원본 ZIP의 1,650개 코드와 연결하는 날짜 증빙은 확보하지 못함**.
- 공식 서비스 공개자료에서 2023년 6월 기준 전통시장 326개 등의 안내가 있어 보관본 전통시장 305개와 수가 불일치. 해당 안내 날짜를 전체 파일에 소급해 유효시작일로 부여하지 않음.
- **G02 BLOCKED 유지**: 검증된 역사적 경계 원본·유효기간이 들어오기 전 `DIM_AREA`에 자동 삽입 금지.

## 3순위 — 업종 분류 버전과 점포 관측기간: 확인 범위

- 공식 **100대 생활밀접업종** 분류표(공식 PDF `100_v3.pdf`) 존재를 확인했다. 보관본 STORE의 100개 업종(음식업 10, 서비스업 47, 소매업 43), SALES 63개의 명칭/코드 일관성 확인. 이는 보관본의 **업종 구조를 확인한 것**이지 공식 **2022년부터 적용된 효력 시작일** 증명은 아니다.
- 서울 점포-상권 공식 공개 구조에는 `기준_년분기_코드`가 존재. 데이터가 분기별 공개된다는 사실은 확인했으나, 개업·폐업·점포 스냅샷의 정확한 관측시점과 별도 `observation_period_key`의 산식을 2022~2023 과거 배포 기준으로 증명하지 못함.
- **G03/G06 BLOCKED 유지**. 분기말을 임의 관측일로, 분기코드를 자동 observation_period_key로 설정하지 않음.

## 최종 실행 안전 원칙

- 추가 코드/분석/문서: `config/phase35_store_semantics_mapping.v1.json`(현재 의미 대응·v0.2 영향), `scripts/simulate_p0_store_quality_policy.py`(읽기 전용), 현재 문서.
- 기존 정제 원본 SRC/STG의 v0.1 기록을 무단 수정하지 않는다.
- 원본 ZIP/개별 상권 행/DB 암호는 공개 리포지토리에 올리지 않는다.
- **실제 DIM·FACT 적재 G02/G03/G06/G11/G13 모두 BLOCKED**.
- 역사적 상권 경계 원문, 분류 버전 효력일, 지표별 관측시점이 공식 문서로 확보되면 다시 게이트 검증을 수행한다.
