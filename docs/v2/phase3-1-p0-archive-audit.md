- 업종코드 유일값: 매출 63개, 점포 100개. 매출에 있는 업종 63개는 모두 점포에 포함되며, 점포에만 있는 업종 37개 존재.
- 매출의 **(년분기, 상권코드, 서비스업종코드)** 조합 125,692개가 전부 점포에도 존재한다. 점포 조합 중 매출이 없는 것은 **331,351개**. 점포→매출 INNER JOIN은 대량 탈락하므로, 매출 없는 업종을 0원으로 치환하지 않는다.
- 영역 파일은 **측정기간/공시버전 컬럼이 전혀 없다**. 이 파일만으로 `DIM_AREA.effective_start_date`를 신뢰할 수 있게 결정할 수 없으므로 보관본/발행일 증빙을 별도로 받아야 한다.

## 3. 실제 입력에서 발견된 무결성 충돌 (BLOCKER)

`sql/v2/p0/001_schema.sql`의 점포 FACT는 다음 조건을 적용한다.

```sql
CHECK (opening_rate IS NULL OR opening_rate BETWEEN 0 AND 100)
CHECK (closure_rate IS NULL OR closure_rate BETWEEN 0 AND 100)
```

**업로드 원본 457,043행을 전수 검사한 결과:**

- `개업_율 > 100`: **5행**, 최대 **200**
- `폐업_률 > 100`: **124행**, 최대 **4800**
- 음수인 개업률/폐업률: **0행**
- 전체 3개 원본에서 빈 문자열/NULL: **관측 0건** (원본 파일에 한함)
- 두 비율 중 하나라도 100을 초과하는 레코드는 **수정 이전 P0 CHECK에서는 적재 오류가 발생한다**. 해당 값을 100으로 클리핑하거나 누락하는 것은 원본 보존 및 지표 해석상 부적절하다.

실제 예: `20221` 분기 / 상권 `3110079` / 업종 `CS200025`의 `점포_수=1`, `폐업_점포_수=2`, `폐업_률=200`. 점포 수 대비 폐업 수가 높아 100 초과가 발생하는 것으로 **추정되지만**, 공식 산식 확인 전 이 값을 오류 또는 정상값으로 단정하지 않는다.

**권고:** Phase 3-2/3-4 진입 전 포털 산식을 검증한 후 점포 개폐업률 CHECK의 상한 100을 제거하거나 올바른 비즈니스 조건으로 변경하고, 원본 회귀 샘플로 검증한다. 기존 P0 negative test(120% 거절)도 변경해야 한다.

## 4. 추가 2022년 매출 파일의 중복/문자 문제

ZIP에 `서울시_상권분석서비스(추정매출-상권)_2022년.csv` 파일이 **별도로 존재**한다.

- **83,573행**이며 모두 통합 매출 파일의 2022년 (분기×상권×업종) 키와 일치.
- 총 **218행**에서 **`상권_코드_명`만 달랐고**, **매출 금액/건수 등 모든 다른 필드는 일치**.
- 예: `종로?청계 관광특구` ↔ `종로·청계 관광특구` — 인코딩/문자치환 흔적이므로 **문자열 명칭이 아니라 상권코드를 JOIN 키로 사용**한다.
- 두 파일을 CONCAT하여 단순 INSERT하면 업무키 중복이 생기므로, 원본 파일 SHA/기준년분기와 우선순위 규칙을 정의해야 한다.
