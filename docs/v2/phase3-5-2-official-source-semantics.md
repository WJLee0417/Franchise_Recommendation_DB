# Phase 3-5-2 — 서울 공식 자료의 공간·업종·점포 관측기간 검증 (2026-10-29)

## 결론: 세 항목 모두 완전 해제 불가, 점포 수치 매핑에서 추가 위험 발견

| 의사결정 대상 | 공식 공개 자료로 확인한 것 | 2022Q1~2023Q2 원본에 대해 아직 확인 못 한 것 | 판단 |
|---|---|---|---|
| 상권 경계·버전 | 서울시 **영역-상권(OA-15560)** 공간 데이터(SHP/좌표계) 서비스 존재; 포털은 상권분석에 표준단위구역 등 공간 개편을 알림 | 과거 1,650개 상권코드가 **어느 원본 공간파일의 어느 [start,end)**에 해당하는지; 경계 폴리곤·개편 이력·실효시점 | **G02 BLOCKED 유지** |
| 업종 분류 | 서울 상권분석서비스의 **100대 생활밀접업종** 분류와 코드 체계; 사용자가 제공한 2022~2023 보관본 점포 CSV에서 100개 코드/명칭이 6개 분기에 걸쳐 일관 | 적용된 **공식 분류 릴리스/발효일**, 변경 및 퇴역 이력, 해당 소스 배포본의 코드북 버전 | **G03 BLOCKED 유지** |
| 점포 관측기간 | 서울시 **점포-상권(OA-15577)**은 **기준_년분기_코드**가 존재하는 분기통계. 2022Q1~2023Q2 원본에 6개 분기코드 | 지표별 **기준일/관측시점**, 예: 분기말 영업 점포 스냅샷인지/기간 영업점포 집계인지, 개·폐업률 분모의 정확한 정의. 별도의 observation_period_key와 관계 | **G06 BLOCKED 유지** |

**중요:** 분기코드가 있다는 사실만으로 보고기간과 관측기간이 같다고 확정할 수 없다. 가용 공식 문서는 **분기 단위 보고**에 대해서는 근거가 되지만, FACT의 별도 관측기간 필드를 자동 채울 근거가 아니다. 또한 공간자료의 **다운로드/게시일은 경계 효력 시작일이 아니다**. 임의 연도 버전이나 공간 변경일을 생성하지 않는다.

## 추가 공식 출처의 중요한 단서

- 서울 공식 **데이터 출처 안내**(https://golmok.seoul.go.kr/source.do)는 골목상권 1,090개·발달상권 249개·전통시장상권 326개·관광특구 6개에 대해 **2023년 6월을 기준시점**으로 표시한다. 하지만 사용자 보관본 AREA는 골목 1,090·발달 249·전통시장 **305**·관광특구 6개로 **1,650개**다. 공식 안내의 전통시장 **326**과 불일치해, 출처 안내 기준시점을 곧바로 이 파일 전체의 버전·유효기간이라고 쓸 수 없다. 원천 파일의 제작·배포 이력을 추가 확인해야 한다.
- 서울 점포-상권 현재 공개 스키마(https://data.seoul.go.kr/dataList/OA-15577/S/1/datasetView.do)에서는 **전체_점포_수, 일반_점포_수, 프랜차이즈_점포_수**를 구별하고 전체=일반+프랜차이즈로 설명한다. 보관본의 `점포_수`와 `유사_업종_점포_수`는 명칭이 달라 현재 스키마로 조용히 바꿔 끼우지 않는다.
- 공식 데이터 출처 안내는 점포 관련 데이터의 **분기** 주기와 2026년 6월 **기준시점**을 별도로 기재한다. 이로써 최신 운영 원천에서 점포 데이터가 분기 단위로 생산된다는 점은 확인되지만, 2022~2023년 HISTORICAL 지표별 스냅샷/개·폐업 분모 기준까지 확정되는 것은 아니다.

## 사용자 제공 역사적 원본 ZIP 직접 검증

`scripts/audit_p0_official_semantics.py`로 3개 원본 CP949 CSV 전체의 SHA-256을 검사하고 코드/집계를 직접 대조했다.

### 업종 코드·명칭의 6개 분기 내부 일관성

| 확인 항목 | 실제 확인 |
|---|---:|
| STORE 업종코드 | **100개** |
| SALES 업종코드 | **63개** (100개에 포함) |
| STORE의 업종코드 수, 각 6분기 | **100개씩** |
| SALES의 업종코드 수, 각 6분기 | **63개씩** |
| STORE 코드에 여러 이름 사용 | **0개** |
| SALES 코드에 여러 이름 사용 | **0개** |
| SALES와 STORE 동일 코드 명칭 불일치 | **0개** |
| STORE 업종코드 접두 분포 | **CS100:10, CS200:47, CS300:43** |

이것은 **분류체계 코드값의 보관본 내부 일관성을 증명**하지만 공식 규정상의 발효일/분류체계 버전까지 증명하지 않는다. 전수 결과를 재생성 가능하도록 코드화했으며 비공개 원본 ZIP/상세 레코드는 GitHub에 올리지 않았다. 현 시점에서 `DIM_INDUSTRY.classification_version='2023'`과 같은 임의값으로 INSERT해서는 안 된다.

### 추가 발견: STORE 데이터의 두 점포 수 컬럼은 같은 지표가 아님

`SRC_SEOUL_STORE`에 매핑된 세 개 원본 컬럼:

- `점포_수` (기존 SRC `store_count`)
- `프랜차이즈_점포_수` (기존 SRC `franchise_store_count`)
- `유사_업종_점포_수` (기존 SRC `similar_industry_store_count`)

**2022Q1~2023Q2의 원본 457,043행 전수에서 아래 항등식이 정확히 성립한다.**

```text
유사_업종_점포_수 = 점포_수 + 프랜차이즈_점포_수
일치 457,043건 / 불일치 0건
```

- `유사_업종_점포_수 > 점포_수`는 **70,337건**, 이 차이는 항상 `프랜차이즈_점포_수` 값과 같다.
- `프랜차이즈_점포_수 > 점포_수`는 **20,323건**. 서로 다른 부분 집계라면 충분히 가능하다.
- 따라서 과거 품질정책의 `유사업종 점포수가 점포수보다 많다`를 이상치로 해석하는 것은 **부적절할 가능성이 매우 높다**. 기존 `P0-DQ-004_SIMILAR_GT_STORE` 경고, `P0-DQ-005_FRANCHISE_GT_STORE` REVIEW는 **재분류 후보**다.
- 서울시 공식 안내의 **전체 점포수 = 일반 점포수 + 프랜차이즈 점포수** 구조와 일치한다. 그러나 역으로 원본의 `유사_업종_점포_수`가 공식 전체 점포수와 완전히 동일한 의미인지, 열 이름이 시대별로 어떻게 변경됐는지는 **과거 코드북 원문을 확인하기 전까지 가설**로 유지한다.
- **새 적재 차단 게이트 G13**: `FACT_AREA_STORE.store_count`가 **일반점포 수**인지 **총점포 수**인지 먼저 결정해야 한다. 현재 SRC의 `store_count`를 그대로 FACT의 총점포로 취급하면 체계적으로 과소계상할 수 있다. 표준화된 분리 필드(ordinary,total,franchise)의 의미를 원문에 근거해 재확정한다.

이번 발견은 기존 정제·품질 판정 **실행 결과 자체를 바꾸지 않는다.** 이미 STG에 기록된 584,385행과 판정 해시는 그대로 남기고, 향후 **새 정제 규칙 버전**을 별도로 승인·재실행한 뒤에만 수정한다.

## 데이터 모델 설계 권고

1. **공간(필수):** 과거 2022/23 `영역-상권`의 원본 SHP와 공간 단위 메타데이터, 코드·경계 개편 공지를 확보해 해당 1,650 코드에 [start,end) 근거를 지정. 불명확하면 `DIM_AREA` 보류.
2. **업종(필수):** 서울시 **100대 생활밀접업종 공식 코드북(과거 적용 버전)**과 효력일을 확보하고 현재 CSV 100개 코드·명칭 매핑을 검증. 현대·공정위 업종코드는 별도 분류체계.
3. **관측기간(필수):** 서울시 점포-상권 공식 필드 정의에서 `기준_년분기`, `개·폐업 점포수`, `개·폐업률`의 관측/분모 기준일을 각각 확인하고, FACT의 `observation_period_key`와 연결 가능한지 결정. 못 하면 `FACT_AREA_STORE` 적재 보류.
4. **점포 카운트 의미(긴급 추가):** `점포_수 + 프랜차이즈_점포_수 = 유사_업종_점포_수` 관계의 공식 의미·산식 확인 → 기존 모델에서 `store_count` 및 `similar_industry_store_count`의 분석 지표명과 정책을 버전업. 원천 컬럼 삭제/변경 금지.
5. **적재 이력/단위:** 분기추정매출 원화 수치의 합계는 그대로 보존, STORE-only 331,351개의 매출 미관측은 NULL 유지. 계보와 SCD2 검증이 끝나기 전 FACT 생성 금지.
